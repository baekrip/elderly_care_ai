### 4-A. 전체 시스템 구성 (3계층)

```
┌──────────────────────────────────────────────────────────────┐
│  LAYER 1  촬영 + 1차 분류 (Edge)                               │
│                                                              │
│  [카메라1] Raspberry Pi 5 + Wide 카메라                         │
│  • 경량 YOLO pose ONNX  →  skeleton 추출                       │
│  • XGBoost (P5-B)      →  1차 행동 분류 (NORMAL/SUSPECT/DANGER)│
│  • Segment Ring Buffer →  위험 clip 임시 저장 (최대 3분)         │
│  • RTSP 스트리밍         →  프론트엔드 실시간 영상               │
│  • T-B JSON 전송         →  Orin Nano로 skeleton + 분류값 전달  │
└──────────────────┬───────────────────────────────────────────┘
                   │  HTTP (LAN)
                   ▼  ActivityFrame + CandidateWindow JSON
┌──────────────────────────────────────────────────────────────┐
│  LAYER 2  정밀 분류 + 엣지 허브 (Edge Hub)                      │
│                                                              │
│  [카메라2+엣지] Jetson Orin Nano 8GB + Wide 카메라              │
│  • 자체 YOLO + XGBoost  →  자체 1차 분류                        │
│  • ST-GCN               →  Pi5 + 자체 후보 2차 정밀 판정         │
│  • Segment Ring Buffer  →  위험 clip 임시 저장                  │
│  • RTSP 스트리밍          →  프론트엔드 실시간 영상               │
│  • 위험 확정 시            →  AWS 백엔드로 JSON + clip 전송       │
└──────────────────┬───────────────────────────────────────────┘
                   │  HTTP (Internet)
                   ▼  ABNORMAL/DANGER events + clip 파일
┌──────────────────────────────────────────────────────────────┐
│  LAYER 3  저장 + 분석 + 알림 (Cloud)                            │
│                                                              │
│  외부 백엔드 서버 (AWS EC2 + Flask + PostgreSQL + S3)           │
│  • events/batch API     →  행동 이벤트 DB 저장                  │
│  • alerts/immediate API →  위험 즉시 알림                       │
│  • S3 clip 저장          →  위험 영상 3분 보관                   │
│  • 2차 AI (패턴 분석)      →  1~2주 생활 패턴 리포트              │
│  • 보호자 웹              →  타임라인 조회 / 알림 / 영상 재생      │
└──────────────────────────────────────────────────────────────┘
```

### 4-B. AI 모델 구동 위치

### 4-C. 데이터 흐름 (타임스탬프 기준)

```
프레임 캡처  →  [capture_ts 기록]
     ↓
YOLO 추론   →  skeleton / bbox 추출
     ↓
XGBoost     →  action_label, xgboost_prob  [xgboost_tier_ms 기록]
     ↓
TriggerEngine  →  위험 후보(CandidateWindow) 생성
     ↓
T-B JSON 전송  →  Orin으로 skeleton + 분류값 전달
     ↓
ST-GCN 추론  →  stgcn_label, 위험 확정  [analysis_ts 기록]
     ↓
위험 확정     →  Pi5에 clip 요청 (clip_start_ms ~ clip_end_ms)
     ↓
clip export  →  segment_ring에서 3분 구간 추출
     ↓
외부 전송     →  /api/v1/alerts/immediate + clip 업로드 → S3
     ↓
보호자 알림   →  웹 팝업 + 영상 바로 재생
```

### 4-D. 상태 레벨 정의

| 레벨 | 정의 | 처리 |
|------|------|------|
| NORMAL | 일반적인 일상 행동 | 로컬 JSONL 저장 (전송 제외) |
| ABNORMAL | 평소와 다른 패턴, 주의 필요 | batch 전송 (10초 단위) |
| DANGER | 즉시 확인 필요, 사고 가능성 | 즉시 알림 + 위험 영상 3분 clip |

### 5-B. 가장 중요한 3가지 병목

```
병목 1: Orin Nano SD카드 미확보
  → 전체 엔드투엔드 테스트가 이것에 막혀 있음
  → SD카드 확보 즉시 T1~T3 테스트 가능

병목 2: Pi5 실기기 FPS 검증 미완
  → P5-B(ONNX CPU)가 실제로 충분한 FPS를 낼 수 있는지 불확실
  → FPS < 5fps 이면 Hailo AI HAT 추가 도입 또는 Pi5는 캡처만 담당(P5-C) 재검토

병목 3: RTSP 실시간 스트리밍 미확정
  → 프론트엔드에서 실시간 영상을 볼 수 없어 서비스 시연 불가
  → MediaMTX + FFmpeg 조합으로 우선 구현 권장
```

**Q. 98.45% 정확도면 실제로도 그 정도 나오나요?**
> 이 수치는 오프라인 검증(학습 데이터 기반) 결과입니다. 실제 카메라 환경(천장 각도, 어둠, 이불 가림 등)에서는 다를 수 있어, 실기기 테스트에서 별도 검증이 필요합니다.

**Q. 오탐(정상을 위험으로 판단) 가능성은 없나요?**
> XGBoost + ST-GCN 2단계 판정 구조로 오탐을 줄였습니다. test.mp4 정상 구간에서 candidate 0개(오탐 없음)를 확인했으나, 운동·스트레칭 등 빠른 움직임에 대한 추가 검증이 필요합니다.

**Q. 카메라가 없는 공간(화장실 등)은 어떻게 처리하나요?**
> 현재는 설계 수준에서 고려 중이며, 카메라 미설치 공간으로의 이동을 'out of frame'으로 인식하고 상태 판단에 반영하는 구조를 향후 추가할 예정입니다.

**Q. 위험 영상 3분은 왜 3분인가요?**
> 낙상 발생 전후 상황을 확인하기 위해 전 90초 + 후 90초 = 3분으로 설정했습니다. 장시간 미활동 등 특수 상황에서는 최대 10분까지 확장되나 그 이상은 저장하지 않습니다.

**Q. 프라이버시 문제는 어떻게 해결하나요?**
> 현재는 기술 구현에 집중하고 있으며, 실제 서비스 전에 동의 기반 운영 정책, 영상 암호화 저장, 접근 권한 관리 등 프라이버시 보호 설계가 추가되어야 합니다.
