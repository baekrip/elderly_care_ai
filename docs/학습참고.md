### 0.2 사용자 수동 라벨 준비

1. 기존 batch registry의 MP4/JSON 쌍을 확인한다.
2. 각 원본 영상/구간에 21개 `activity_label` 중 하나와 3개 `risk_label` 중 하나를 사람이 지정한다.
3. 같은 원본 영상에서 나온 frame/window는 같은 `sample_id`를 유지한다.
4. 각 activity class는 서로 다른 원본 영상 group 2개 이상을 준비한다. 부족하면 trainer dry-run이 실패한다.
5. validation 원본 영상은 training 원본 영상과 겹치지 않게 별도 보관한다.

이 단계는 사람 검수 작업이다. 자동 pseudo-label만으로 validation 정답을 만들지 않는다.

JSONL은 한 줄에 JSON 객체 하나다. 최소 행 계약은 아래와 같다. 예시 값을 그대로 학습 데이터로 쓰지 않는다.

```json
{"sample_id":"원본영상ID","activity_label":"standing","pose_jsonl":"같은_폴더_안의_pose.jsonl"}
{"sample_id":"원본영상ID","frame_index":0,"activity_label":"standing","risk_label":"normal","keypoints":[[0.0,0.0,0.9]]}
```

두 번째 예시의 `keypoints`는 설명 축약본이다. 실제 행은 관절 17개 각각 `[x,y,confidence]`를 가져야 한다. `activity_label`은 21개 계약 중 하나, `risk_label`은 `normal/abnormal/danger` 중 하나여야 한다.

## 0.C 세부 행동 분류(Multi-task Activity) 모델 학습 절차 (2026-06-17 신규)

목표: 기존 이진 판단(NORMAL/DROP)을 넘어 21개 activity_label(일상행동 세부 분류)과 3-class risk_head를 동시에 학습하는 Dual-head ST-GCN 모델 및 XGBoost static/posture 분류기를 구현·학습한다.

> **전제**: XGBoost tier multiclass(Accuracy 100%)와 ST-GCN fall-binary(Accuracy 97.5%) 기존 모델 학습 완료 상태.

### 0.C.0 확정 설계 사항

| 항목 | 결정 |
|---|---|
| activity label 체계 | `0.A.1` 목표 라벨 21개 그대로 사용 |
| 데이터 출처 | 기존 MP4+JSON batch registry(독거노인 일상행동 영상) 활용 |
| activity_label 확보 | batch registry에서 export 도구로 자동 정제 + 사람이 segment별 직접 라벨링 |
| 모델 연계 | Late Fusion (XGBoost, ST-GCN 독립 학습 → FSM/Fusion 단 결합) |
| ST-GCN 구조 | Dual-head: activity_head(21-class) + risk_head(3-class), risk_label은 tier_label 매핑 |
| 구현 순서 | XGBoost export → 학습 → ST-GCN sequence export → 학습 (순차) |
| gate 기준 | `0.A.5` 기준 (Accuracy 95%+, Danger Recall 97%+, Latency 1.5ms-, 30 FPS AND 조건) |

### 0.C.1 1단계: XGBoost static/posture 도구 개발 및 학습

**목적**: `standing`, `sitting`, `lying_rest` 같은 정적 자세를 XGBoost로 빠르게 추론하는 보조 분기 생성.

### 0.C.2 2단계: ST-GCN Activity Dual-head 도구 개발 및 학습

**목적**: 21개 세부 행동 + 3-class 위험도를 skeleton sequence로 동시 학습.

#### 2-1. export_stgcn_activity_sequences.py 구현 완료

역할: batch registry의 MP4+JSON에서 skeleton sequence (.npz)를 activity_label + risk_label(tier_label 매핑)로 export.

## 0.B 일상추론 수동 재학습 준비 완료 계획

목표: 낙상 이진 판단만이 아니라 `activity_label`(일상 행동)과 `risk_label`(위험도)을 분리해 저장할 수 있는 수동 재학습 준비를 완료한다. 실제 학습 실행은 사용자 승인 전 진행하지 않는다.

### 0.B.1 완료된 준비

| 항목 | 상태 |
|---|---|
| 환자 식별값 | 런타임 config, 테스트, 스트림 경로 기준값을 `P001`로 사용한다. API/DB 필드명은 계약상 `patient_id`를 유지하고 값만 `P001`로 보낸다. |

| 일상추론 학습 도구 | `tools/train_stgcn_activity.py` 구현 완료. shared backbone + activity head + risk head 구조 |
| 평가 도구 | `tools/evaluate_model.py` 구현 완료. accuracy, precision, recall, confusion matrix, gate 판정용 |
| backend 검증 경로 | `events/batch`, `alerts/immediate`, `clips/upload-url`, `clips/confirm` 기준 정리 완료 |
| 수동 학습 금지선 | Codex 자동 학습 실행 금지. 사용자가 직접 실행 후 결과를 알려주면 검증/배포 준비만 진행 |

### 0.B.2 수동 학습 전 남은 입력 데이터 조건

| 필요 데이터 | 이유 | 없을 때 처리 |
|---|---|---|
| 세부 행동 라벨 sequence `.npz` | `activity_label` 학습 입력 | `export_stgcn_activity_sequences.py` 구현 또는 수동 변환 필요 |
| risk tier 라벨 | `risk_label` 학습 입력 | 기존 `tier_label` 기반 XGBoost만 먼저 학습 |
| validation split | 기존 모델과 새 모델 비교 | 배포 금지, report만 생성 |
| per-event eval JSONL | fusion weight calibration | grid search 실행 보류 |

### 0.B.3 수동 재학습 순서

```text
1. P001 기준 MP4/JSON batch 등록
2. 세부 행동 라벨 검수
3. XGBoost risk tier feature export
4. XGBoost risk tier 수동 학습
5. ST-GCN fall-binary sequence export
6. ST-GCN fall-binary 수동 학습
7. activity/risk multi-task sequence 준비
8. train_stgcn_activity.py 수동 학습
9. evaluate_model.py로 기존 모델 대비 평가
10. gate 통과 시 device_transfer/Edge 모델 반영 준비
11. Pi5/Orin local smoke 및 backend event/clip smoke
```

### 0.B.4 완료 판정

- `patient_id` 필드값이 backend 전송 payload에서 `P001`로 들어간다.
- 일상 행동은 `activity_label`, 위험도는 `risk_label`로 분리된다.
- accuracy는 전체 샘플 중 맞춘 비율, precision은 위험 예측 중 실제 위험 비율, recall은 실제 위험 중 놓치지 않은 비율로 report에 표시한다.
- 새 모델이 기존 모델보다 DANGER/DROP recall을 낮추면 교체하지 않는다.
- 30 FPS 스트리밍 안정성을 깨면 모델 교체하지 않는다.

## 0.A 목표 기준 학습 순서

### 0.A.0 현재 발표 목표 우선 완료 게이트

학습과 학습검증은 아래 발표 목표가 확인된 뒤 진행한다. 이 단계가 실패하면 신규 학습보다 전송/스트리밍 경로를 먼저 고친다.

1. Pi5 `BACKEND_URL=54.116.119.98` 주입 시 `stream.output_url`이 런타임에서 `rtsp://54.116.119.98:8554/P001`로 오버라이드되는지 확인한다.
2. WebRTC 시청 주소는 `http://54.116.119.98:8889/P001/` 기준으로 확인한다.
3. Pi5 영상 overlay는 bbox/keypoint/skeleton/status만 표시한다. Pi5의 `UNKNOWN NORMAL`은 행동추론 결과가 아니므로 최종 표시 대상에서 제외한다.
4. 행동/위험 판단은 Orin 추론 후 backend `events/batch` 저장 결과와 `POST /api/v1/alerts/immediate` 응답으로 확인한다.

### 0.A.4 목표 구조에 추가로 필요한 학습 도구

아래 항목은 목표 기준상 필요하며, 일부 개발 완료된 도구 외에 남은 부분은 순차적으로 완성한다.

| 필요 도구 | 역할 | 현재 상태 |
|---|---|---|
| `tools/export_xgboost_static_features.py` | 6-class posture feature 생성 | 구현 완료 |
| `tools/train_xgboost_static_posture.py` | XGBoost static/posture classifier 학습 | 구현 완료 |
| `tools/export_stgcn_activity_sequences.py` | 21-class activity sequence 생성 | 구현 완료 |
| `tools/train_stgcn_activity.py` | shared backbone + `activity_head` + `risk_head` 학습 | 구현 완료 |
| `tools/evaluate_model.py` | validation 전용 모델 비교 평가 | 구현 완료 |

개발 순서:
1. `shared/labels.py`에 목표 activity/risk label enum과 label map을 고정한다.
2. batch registry에서 세부 행동 라벨 누락/중복을 검사한다.
3. `export_xgboost_static_features.py`를 만든다.
4. `train_xgboost_static_posture.py`를 만든다.
5. `export_stgcn_activity_sequences.py`를 만든다.
6. `train_stgcn_activity.py` dual-head 학습 입력 스키마와 sequence export 결과를 맞춘다.
7. `evaluate_model.py`로 같은 validation 자료에서 기존 모델과 새 모델을 비교한다.
8. 통과 모델만 `device_transfer/Edge`에 반영한다.

### 0.A.5 목표 기준 통과 조건

학습 완료 뒤 아래 조건을 모두 만족해야 운영 적용한다.

| 기준 | 통과 조건 |
|---|---|
| 라벨 품질 | 목표 라벨 누락, 중복, 불명확 라벨이 report에 남지 않음 |
| XGBoost tier | 기존 운영 모델보다 DANGER recall 하락 없음 |
| ST-GCN fall | 기존 운영 모델보다 DROP recall 하락 없음 |
| 세부 행동 모델 | validation에서 정상 일상 라벨과 위험 전조 라벨 confusion matrix 확인 |
| false positive | 정상 걷기/앉기/눕기/스트레칭이 DANGER로 증가하지 않음 |
| latency | Orin ST-GCN/XGBoost 병렬 추론이 실기기에서 frame drop을 만들지 않음 |
| backend JSON | 실기기 Pi5 -> Orin -> backend `events/batch` `201` 응답 id 기록 |
| backend clip | 위험 clip이 Orin local DB와 backend media DB에 각각 clip id로 기록 |
| overlay | 브라우저 수동 확인에서 Pi5 영상 bbox/keypoint/skeleton/status 표시, 행동/위험은 backend SSE 또는 JSON 패널에서 확인 |

### 0.A.6 실패 시 수정 순서

```text
DANGER recall 하락
  -> 위험 라벨 누락 확인
  -> fall/near_fall/stumble hard example 추가
  -> threshold/window/FSM 수정
  -> 재학습 또는 기존 모델 유지

NORMAL false positive 증가
  -> 정상 hard negative 추가
  -> XGBoost threshold 상향
  -> smoothing/FSM duration 조정
  -> validation 재검증

세부 행동 confusion 증가
  -> 라벨 정의 재확인
  -> activity sequence window 길이 조정
  -> ST-GCN activity/risk head loss weight 조정
  -> validation 재검증

FPS/latency 악화
  -> FP16/ONNX/TensorRT 후보 비교
  -> stride/window 주기 조정
  -> 30 FPS stream 기준과 AI 추론 FPS 기준 분리 기록
```

## 0.4 검증 이후 순서

사용자가 학습을 수동 완료한 뒤 Codex가 아래 순서로 자동 진행한다.

1. 학습 산출물 존재 확인.
   - XGBoost: `device_transfer\Edge\edge\models\xgboost_tier_multiclass.json`
   - ST-GCN: `device_transfer\Edge\server\models\stgcn_fall_binary.pth`
   - YOLO pose: 학습 output 경로와 `best.pt` 또는 사용자가 지정한 모델 파일
2. 학습 report 확인.
   - XGBoost: `experiments\behavior_training\reports\xgboost_tier_multiclass_meta.json`
   - ST-GCN: `experiments\behavior_training\reports\stgcn_train_report_fall.json`
   - YOLO pose: 학습 결과 폴더의 metrics/results 파일
3. 새 모델 지표가 기존 모델보다 나은지 확인한다.
4. `recall`, `precision`, `confusion matrix`, YOLO pose dataset gate, 실기기 FPS gate를 모두 통과했는지 확인한다.
5. 하나라도 실패하면 기존 모델을 유지한다.
6. 모두 통과하면 모델 파일을 운영 경로에 교체한다.
7. 로컬 테스트를 실행한다.
   - device config
   - remote device ops
   - RTSP streamer
   - training batch/gate tools
8. 로컬 통합 MP4 smoke를 실행한다.
9. 내부 overlay viewer를 실행해 행동/위험 label, bbox/keypoint, FPS 표시를 확인한다.
10. `tools\build_deploy_bundles.py`로 `device_transfer\camera1`, `device_transfer\Edge` 구조를 검증한다.
11. Pi5/Orin에 최신 구조를 배포한다.
12. 배포 후 Orin health, Pi5 clip server, skeleton WS, danger e2e, RTSP/WebRTC, performance window를 다시 확인한다.
13. 외부 backend/S3 credential이 준비되어 있으면 backend live smoke를 진행한다.
14. `docs\진행상황.md`에 모델 교체 결과와 gate 수치를 기록한다.
15. 실패하거나 보류된 항목은 `docs\구성.md`의 `문제점과 해결방안`에만 남긴다.

순서도:

```text
새 영상+라벨 투입
  -> batch 등록
  -> XGBoost feature batch 생성
  -> ST-GCN sequence batch 생성
  -> MP4에서 YOLO pose pseudo-label frame/JSONL 생성
  -> pseudo-label 육안 검수 + 자동 검증
  -> YOLO pose dataset 생성
  -> YOLO pose dataset gate 통과
  -> batch merge
  -> 사용자가 수동 학습 실행
  -> 사용자가 "학습 완료" 알림
  -> Codex가 label/model/local/device/backend gate 자동 검증
  -> 전부 통과: 모델 교체 + device_transfer 구조 검증 + 실기기 배포
  -> 하나라도 실패: 기존 모델 유지 + 문제점 기록
```

---

이 문서는 사용자가 직접 XGBoost/ST-GCN 재학습을 실행할 때 보는 순서형 명령 가이드다. Codex는 사용자가 명시적으로 요청하기 전에는 학습을 자동 실행하지 않는다.

## 8. 결과 판정 기준

모델 교체 전 반드시 확인한다.

정확도 설명:
- accuracy: 전체 샘플 중 맞춘 비율.
- precision: 위험이라고 판단한 것 중 실제 위험인 비율.
- recall: 실제 위험 중 모델이 놓치지 않고 잡은 비율.
- 낙상/위험 감지는 accuracy보다 recall 하락 여부가 더 중요하다.

## 12. validation 자료 검증 후 수정 절차

학습 결과는 training 결과만으로 운영 적용하지 않는다. 반드시 학습에 쓰지 않은 validation 자료로 검증하고, 실패 원인을 분리한 뒤 수정한다.

### 12.1 validation 자료 분리 기준

validation 자료는 training 입력과 섞이면 안 된다.

권장 구조:

```text
experiments\behavior_training\validation\
├── videos\        ← 학습에 쓰지 않은 MP4
├── labels\        ← 같은 stem의 JSON 라벨
├── reports\       ← 검증 리포트
└── failures\      ← 오분류 샘플/프레임 분류
```

분리 규칙:
- 같은 사람, 같은 촬영 구간, 같은 원본 영상에서 잘라낸 clip은 train과 validation에 동시에 넣지 않는다.
- `NORMAL`, `ABNORMAL`, `DANGER`가 모두 있어야 한다.
- 위험 validation에는 `fall_candidate`, `fall_confirmed`, `fall_then_no_move`, `near_fall`, `stumble` 같은 경계 사례를 포함한다.
- 정상 validation에는 걷기, 앉기, 눕기, 스트레칭, 빠른 움직임처럼 오탐이 나기 쉬운 사례를 포함한다.
- validation label은 사람이 확인한 라벨만 사용한다. pseudo-label만 있는 frame은 validation 기준으로 쓰지 않는다.

### 12.2 validation 실행 순서

1. validation MP4/JSON을 별도 폴더에 둔다.
2. validation 전용 feature/sequence를 만든다.
3. 새 모델을 validation 자료에만 적용한다.
4. 기존 모델과 새 모델의 지표를 같은 validation 자료에서 비교한다.
5. 실패 샘플을 `false_positive`, `false_negative`, `label_error`, `pose_error`, `temporal_error`로 분류한다.
6. 수정 후 같은 validation 자료로 다시 검증한다.

XGBoost validation feature 생성 예:

```powershell
.\.venv_edge_local\Scripts\python.exe tools\export_xgboost_tier_features.py --jobs experiments\behavior_training\validation\xgboost_validation_jobs.jsonl --label-mode tier --output-csv experiments\behavior_training\validation\xgboost_validation_features.csv
```

ST-GCN validation sequence 생성 예:

```powershell
.\.venv_edge_local\Scripts\python.exe tools\export_stgcn_sequences.py --jobs experiments\behavior_training\validation\stgcn_validation_jobs.jsonl --label-mode fall_binary --include-labels NORMAL,DROP --output experiments\behavior_training\validation\stgcn_validation_sequences.npz --meta-out experiments\behavior_training\validation\reports\stgcn_validation_meta.json
```

현재 저장소에는 임의 모델 파일을 독립 validation 데이터셋으로 평가하는 전용 `tools/evaluate_model.py`가 아직 확정 구현되어 있지 않다. 전용 평가 도구가 없으면 기존 학습 report, `tools.check_model_gate`, 통합 MP4 smoke, 실기기 gate를 함께 사용해 검증한다. 전용 평가 도구 개발은 `docs/구성.md`의 개선방안 16 기준으로 진행한다.

### 12.3 validation 판정 기준

| 항목 | 통과 기준 | 실패 시 의미 |
|---|---|---|
| DANGER recall | 기존 모델보다 낮아지면 교체 금지 | 실제 위험 누락 증가 |
| DANGER precision | 기존 모델보다 낮아지면 보류 | 보호자 오탐 알림 증가 |
| NORMAL false positive | 증가하면 보류 | 일상 행동을 위험으로 오판 |
| confusion matrix | DANGER→NORMAL 증가 금지 | 위험 미탐 |
| validation FPS | 실기기 기준 하락 시 보류 | 모델 무거움 또는 frame drop |
| overlay 확인 | bbox/keypoint/action label 불일치 시 보류 | 화면 표시와 판단 결과 불일치 |

판정 우선순위:
1. DANGER recall 하락이면 운영 교체 금지.
2. DANGER precision 하락이면 threshold/window 수정 후 재검증.
3. NORMAL false positive 증가면 정상 hard negative를 추가하고 재학습.
4. FPS 하락이면 모델 경량화, stride, 해상도, TensorRT/ONNX 최적화를 먼저 검토.

### 12.4 실패 유형별 수정 방법

| 실패 유형 | 증상 | 먼저 수정할 것 | 다시 할 검증 |
|---|---|---|---|
| `false_negative` | 실제 위험인데 NORMAL/ABNORMAL으로 판단 | 위험 라벨 누락 확인, DANGER sample 추가, recall threshold 조정 | validation recall, danger e2e |
| `false_positive` | 정상인데 DANGER로 판단 | 정상 hard negative 추가, threshold 상향, FSM 지속시간 보정 | precision, NORMAL replay |
| `label_error` | 라벨 자체가 영상과 다름 | JSON 라벨 수정, sample_id 중복 확인 | label quality gate |
| `pose_error` | bbox/keypoint가 사람을 못 잡음 | YOLO pseudo-label 제거/수정, 저조도/가림 frame 분리 | YOLO pose dataset gate |
| `temporal_error` | 순간 프레임은 맞지만 시간 흐름 판단 실패 | ST-GCN window 길이, smoothing, event FSM 보정 | ST-GCN validation, integrated video smoke |
| `latency_error` | 정확도는 좋지만 FPS/지연 악화 | 모델 크기, stride, TensorRT FP16, batch/window 주기 조정 | 실기기 performance window |

### 12.5 수정 루프

validation 실패 시 아래 순서를 반복한다.

```text
validation 실패 확인
  -> 실패 샘플 분류
  -> 라벨 오류면 라벨 수정
  -> 데이터 부족이면 train에 hard example 추가
  -> threshold/window 문제면 설정값 수정
  -> 모델 한계면 재학습
  -> validation 재검증
  -> local smoke
  -> 실기기 gate
  -> 통과 시 device_transfer 모델 교체 유지
  -> 실패 시 기존 모델 유지
```

기록 위치:
- 실패 샘플 목록: `experiments\behavior_training\validation\failures\*.jsonl`
- validation 리포트: `experiments\behavior_training\validation\reports\*.json`
- 최종 판정: `docs\진행상황.md`
- 남은 문제와 해결방안: `docs\구성.md`

운영 적용 금지 조건:
- validation 자료 없이 training accuracy만 높은 경우.
- DANGER recall이 기존 모델보다 낮은 경우.
- normal 활동의 DANGER false positive가 증가한 경우.
- Pi5/Orin 실기기 FPS 또는 frame drop이 기존보다 나빠진 경우.
- JSON 전송, 위험 clip 전송, backend DB 저장 중 하나라도 검증되지 않은 경우.
