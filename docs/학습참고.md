### 반드시 지킬 경계

1. Data1 JSON의 `annotations.resource.resourcePath` PID는 `split_group_id`로만 사용한다. 이는 익명 구조 식별자이며 실제 사람 또는 session ID가 아니다.
2. 같은 PID의 Data1 MP4/JSON은 항상 같은 split에 둔다. 이 split은 PID 구조 누수 방지용이며 subject-independent 성능으로 해석하지 않는다.
3. 사용자가 제공한 프로젝트 명세에 따라 `ABNOR_W`는 `standing`, `sitting`, `walking` 후보가 포함된 source로 사용한다. 원본 `actionName`의 `W11W22` 같은 복합 W-code를 공식 codebook으로 해석했다고 주장하지 않으며, 현재 activity 입력은 `coarse-rule-teacher-v1` 기반 pseudo-label이다. `human_reviewed=false`를 유지하고 사람 정답으로 승격하지 않는다. `M_I_001`, `M_I_004`, `M_I_007`도 공식 semantic mapping으로 확정하지 않는다.
4. `room_exit`, `no_move_long`은 이미지 단일 프레임 class가 아니라 runtime ROI/time rule이다. YOLO pose 학습 label이나 ST-GCN/XGBoost class로 자동 생성하지 않는다.
5. Data1 JSON에는 COCO-17 keypoint ground truth가 없다. teacher pose는 `AUTO_GENERATED` 후보이며 정답이 아니다. 자동 품질 검증을 통과한 `AUTO_QUALITY_APPROVED`도 사람 정답이 아니라 고정된 자동 gate를 통과한 pseudo-label이다. 해당 report에는 `approval_mode=automatic_quality_gate`, `human_reviewed=false`를 명시한다.
6. `video/validation` 경로가 input manifest, operation, dataset YAML에 한 건이라도 섞이면 즉시 중단한다.

수동 review page와 `pose_review_operations.json` 절차는 사용하지 않는다. 자동 경로는 다음 상태만 사용한다.

```text
AUTO_GENERATED
  ├─ 자동 품질 gate PASS  -> AUTO_QUALITY_APPROVED
  └─ 자동 품질 gate FAIL  -> AUTO_REJECTED
```

`AUTO_QUALITY_APPROVED`를 `HUMAN_REVIEWED` 또는 `HUMAN_CORRECTED`로 변환하지 않는다. activity pseudo dataset에는 `label_provenance`, `source_label_specification`, `sequence_label_purity`, `human_reviewed=false`를 남긴다. 현재 산출물은 학습 입력 형식과 고정 split을 만족하지만 semantic truth가 사람 검수로 확정된 것은 아니다. 학습 후에는 반드시 별도 validation/evaluation으로 성능을 확인한다.

### 2.1 2026-07-17 최신 실행 검증 및 배포 상태

학습과 고정 split 상세평가는 완료됐다. 아래 수치는 현재 저장 model을 읽어 `train_val`만 재평가한 결과이며, 학습이나 재분할을 다시 수행하지 않았다.

| 대상 | 결과 |
|---|---|
| XGBoost | `721/759 = 0.949934`; balanced accuracy `0.852713`; macro F1 `0.895483`; `lying` recall `0.558140` (`48/86`) |
| ST-GCN activity | `15/24 = 0.625`; balanced accuracy `0.55`; macro F1 `0.527333`; `lying` support `1`, recall `0` |
| ST-GCN risk | `19/24 = 0.791667`; macro F1 `0.782540`; `danger` recall `0.8` (`4/5`) |
| Integrity | XGBoost 52-feature exact order, ST-GCN `[98,60,17,3]`, fixed split/group overlap, finite output, SHA-256 `PASS` |
| Checkpoint | `best_state`가 성능 갱신 시 `cpu().clone()`으로 저장되며 report 최고 epoch는 `35` |
| Shadow deployment | bundle 복사 후 재로드·재평가 prediction hash 일치 `PASS`; `alerts_enabled=false` |
| 운영 배포 | `BLOCKED`; 현재 장치 runtime은 legacy `MiniSTGCN/24-frame`, 저장 모델은 `MultiTaskSTGCNFixedSplit/60-frame` |

현재 가능한 배포 범위는 로컬 shadow 추론 bundle뿐이다. 운영 알림을 활성화하려면 현재 model용 60-frame exporter/runtime adapter, host/device parity, `sleeping/room_exit/no_move_long` rule, `UNKNOWN`과 fusion, 대표성 있는 추가 validation이 먼저 필요하다. activity label은 `coarse-rule-teacher-v1` 자동 pseudo-label이며 `human_reviewed=false`이므로 사람 검수 semantic truth로 해석하지 않는다.

### 자동 검증 및 interval 신규 계약

다음 모듈은 현재 저장소에 구현되어 있다. `--help`와 focused test가 통과하지 않으면 문서의 다음 명령을 실행하지 않는다.

1. `tools.auto_validate_pose_candidates`
   - 후보 JSONL과 frame 파일을 읽어 자동 품질 판정을 생성한다.
   - 각 record를 `AUTO_QUALITY_APPROVED` 또는 `AUTO_REJECTED`로만 판정한다.
   - 원본 record를 수정하지 않고 decisions/report를 별도 저장한다.
2. `tools.materialize_auto_validated_pose`
   - 후보와 decisions를 결합해 승인 record만 새 JSONL로 materialize한다.
   - provenance, split, manifest hash, frame hash를 그대로 보존한다.
3. `tools.materialize_data1_activity_intervals`
   - 공식 codebook, source specification, 사람의 구간 annotation만 `VERIFIED` interval로 허용한다.
   - canonical split manifest의 source video, split, PID를 상속하고 `video/validation` 및 미확정 label을 거부한다.
   - 오류가 한 건이라도 있으면 output records를 비우고 `BLOCKED` report를 작성한다.
4. `tools.build_data1_confirmed_fall_intervals`
   - 현재 문서에서 확정된 `ABNOR_H -> fall_down`만 `source_specification` + `VERIFIED`로 생성한다.
   - `M_I_001`, `M_I_004`, `M_I_007`은 unresolved로 유지하고 `full_learning_ready=false`를 기록한다.
5. `tools.build_data1_confirmed_fall_pose_registry`와 `tools.attach_data1_activity_interval_provenance`
   - verified interval과 일치하는 source sample만 pose 추론에 사용한다.
   - frame이 verified interval 밖이거나 split/PID/source hash가 다르면 전체 output을 비우고 `BLOCKED`로 끝낸다.
6. `tools.extract_yolo_pose_pseudo_labels`
   - `--teacher-model`을 지정하면 teacher checkpoint SHA-256을 반드시 계산한다.
   - hash 실패 또는 빈 hash는 `teacher_model_hash_failed` report를 작성하고 non-zero로 종료하며 pose output을 생성하지 않는다.

`tools.build_yolo_pose_dataset`도 다음 계약을 추가해야 한다.

- `--approval-report`와 `--approval-mode automatic_quality_gate`를 받는다.
- 입력 record가 전부 `AUTO_QUALITY_APPROVED`인지 재검증한다.
- report의 source manifest hash와 policy hash가 모든 입력 record와 일치하고, `approved_rows`가 입력 행 수와 같을 때만 `training_allowed=true`를 기록한다.
- `human_review`에서 품질 기준 미달 행은 label 파일을 만들지 않고 `BLOCKED` report와 review item으로 남긴다.
- `human_reviewed=false`를 report에 기록한다.
- `HUMAN_REVIEWED`를 자동으로 생성하거나 요구하지 않는다.

현재 검증된 기존 option 이름을 임의로 바꾸지 않는다. 신규 option은 코드와 test를 함께 구현한 후 사용한다.

split manifest hash는 JSON 안의 오래된 임의 hash가 아니라 현재 `$SplitManifest` 파일 byte의 SHA-256을 사용한다.

```powershell
$RegistryRows = Get-Content -LiteralPath $RegistrySplit -Encoding UTF8 |
```

8. YOLO26x-pose teacher를 이용한 Data1 pose 후보 재생성
8.1 기존 YOLO26n self-training 결과 (기록 유지)
기존 경로는 yolo26n-pose.pt가 생성한 pseudo-label로 동일한 yolo26n-pose.pt를 재학습했다. 내부 train_val 234개 기준 결과는 다음과 같다.

지표	기본 yolo26n-pose	Fine-tuned best.pt	변화
Box mAP50	0.9571	0.9356	-0.0215
Box mAP50-95	0.7644	0.6751	-0.0893
Pose mAP50	0.7560	0.6368	-0.1192
Pose mAP50-95	0.3441	0.2381	-0.1060
Pose Recall	0.7607	0.6709	-0.0897
판정: 학습 실행 PASS, checkpoint 생성 PASS, 성능 개선 FAIL → fine-tuned best.pt REJECT, 기본 yolo26n-pose.pt APPROVE(유지). 이후 pseudo-label teacher는 yolo26x-pose.pt로 교체하고, 배포 대상 student는 yolo26n-pose.pt로 유지한다.

8.2 Teacher–student 고정 계약

$StudentPoseModel = ".\yolo26n-pose.pt"

$TeacherImgSz = 640
$StudentImgSz = 480

if (-not (Test-Path -LiteralPath $TeacherPoseModel -PathType Leaf)) {

10.1 자동 검증 원칙

12. ST-GCN·XGBoost를 이용한 8개 행동 출력 계약
12.1 목표 행동 라벨과 판정 방식
최종 외부 출력 라벨은 8개: standing, sitting, walking, lying, sleeping, fall_down, room_exit, no_move_long.

라벨	성격	주 판정 방식
standing	정적 자세	XGBoost + ST-GCN
sitting	정적 자세	XGBoost + ST-GCN
walking	시간적 움직임	ST-GCN
lying	정적 자세 + 짧은 시간 문맥	XGBoost + ST-GCN
sleeping	누운 자세 + 침대 ROI + 장시간 저동작	규칙/fusion
fall_down	급격한 자세 전이 + 최종 누운 자세	ST-GCN + XGBoost/fusion
room_exit	출입구 ROI 통과 + 사람 부재	tracking/ROI 규칙
no_move_long	일정 시간 이상 저동작	시간 누적 규칙
잘못된 구조: ST-GCN 또는 XGBoost 단독으로 8개 전부 분류. 권장 구조: XGBoost가 자세 확률 생성 → ST-GCN이 시간 행동 확률 생성 → ROI/time rule이 장기 이벤트 생성 → fusion policy가 최종 8-label을 결정한다.

12.2 내부 UNKNOWN 상태
8개 외부 라벨과 별개로 내부 abstention 상태 UNKNOWN을 반드시 둔다. low confidence, missing keypoints, multiple people, ROI unavailable, insufficient duration, model disagreaement 상황에서는 8개 중 하나를 강제 출력하지 않고 UNKNOWN으로 보낸다.

12.3 8-label의 전제 조건
현재 activity preparation은 두 provenance 경로를 구분한다. `ABNOR_H -> fall_down`은 source risk/interval의 강한 근거이고, 사용자가 제공한 프로젝트 명세의 `ABNOR_W` standing/sitting/walking 후보는 activity pseudo-label 생성에 사용한다. 원본 W-code를 공식 codebook으로 번역한 것은 아니다. `M_I_*`와 `ABNOR_W`의 프레임별 activity는 `coarse-rule-teacher-v1`, sequence-level ST-GCN label은 `coarse-rule-teacher-v1_sequence-majority-v1`로 표시하며 `human_reviewed=false`를 유지한다. 위험도 보조 계약은 `M_I_001/004/007 -> normal`, `ABNOR_W -> abnormal`, `ABNOR_H -> danger`이다.

Data1 제공 기관의 공식 action-code 사전

action code 의미가 명시된 원본 specification

각 영상 행동 구간에 대한 사람의 구간 라벨링

M_I_001=standing, M_I_004=sitting, M_I_007=walking 같은 추측 매핑은 공식 근거 없이 사용하지 않는다.

12.7 ST-GCN target contract
1차 target 5개: 0=standing, 1=sitting, 2=walking, 3=lying, 4=fall_down. 필요 조건: 각 클래스 train_fit/train_val sequence 존재, 각 클래스 다수 source video·PID group 존재, cross-split PID/source overlap=0, UNKNOWN sequence=0, video/validation sequence=0.

고정 split 학습은 기존 8-class/internal split trainer와 분리된 `tools.train_stgcn_fixed_split`을 사용한다. 이 adapter는 NPZ의 `splits`, `split_group_ids`, 5-class activity, 3-class risk를 직접 검증하고 내부 random split을 만들지 않는다. 실제 학습은 완료됐고, report history 50개에서 최고 epoch `35`를 확인했다. `tools.stgcn_activity_model.train_one_run`은 성능 갱신 시 `cpu().clone()`한 `best_state`를 반환하며 trainer는 그 상태를 `.pth`에 저장한다.

fall_down sequence는 낙상 후 누운 frame만이 아니라 pre-fall, fall transition, impact(급격한 높이 변화), post-fall lying을 모두 포함해야 한다. 그렇지 않으면 ST-GCN이 낙상 동작이 아니라 단순 lying 자세만 학습할 위험이 있다.

12.9 Sleeping 판정
조건 결합: posture=lying, track가 bed ROI 내부, 일정 시간 이상 낮은 관절 이동량, room_exit 상태 아님, fall_down 직후 suppression 기간 종료.

text
lying_probability >= frozen threshold
AND inside_bed_roi = true
AND motion_score <= frozen threshold
AND duration >= configured sleeping duration
→ sleeping
threshold와 duration은 내부 train_val 및 별도 development calibration data로 결정·동결하며, 외부 video/validation을 보고 반복 수정하지 않는다.

12.10 Room-exit 판정
pose 분류 클래스가 아니라 camera별 exit ROI, person track ID, ROI 진입/통과 방향, track 소실 시점, 재등장 grace period가 필요하다.

text
person track가 exit ROI를 정상 방향으로 통과
AND 일정 시간 동안 frame 내 person이 없음
→ room_exit
단순 pose detection 1-frame 실패를 room_exit으로 처리하지 않는다.

12.11 No-move-long 판정
text
motion_score <= frozen threshold
AND duration >= configured no-move duration
AND sleeping = false
→ no_move_long
person track 유지, 일정 시간 이상 저동작 지속, sleeping policy로 설명되지 않음, room_exit 상태 아님이 전제 조건이다. XGBoost 단일 frame 결과만으로 출력하지 않는다.

12.12 최종 8-label fusion
각 component 출력: XGBoost(P(standing), P(sitting), P(lying)), ST-GCN(P(standing), P(sitting), P(walking), P(lying), P(fall_down)), Rule engine(sleeping_event, room_exit_event, no_move_long_event).

권장 우선순위: 1.fall_down → 2.room_exit → 3.sleeping → 4.no_move_long → 5.walking → 6.lying → 7.sitting → 8.standing → 9.내부 UNKNOWN. 우선순위·threshold·suppression time은 experiments/behavior_training/config/activity_fusion_policy_v1.json에 versioned policy로 저장한다.

12.13 8-label 학습·평가 완료 조건
다음을 모두 만족해야 한다: 공식 코드북 또는 검증된 행동 구간 label manifest 존재, standing/sitting/walking/lying/fall_down 구간 모두 존재, 각 학습 클래스 train_fit·train_val 존재, 연속 pose sequence 생성 가능, XGBoost feature schema 고정, ST-GCN sequence schema 고정, PID/source split leakage=0, camera별 bed ROI·exit ROI 정의, sleeping/no_move_long duration policy 정의, 최종 fusion priority 정의, UNKNOWN abstention 구현, 최종 evaluator가 8-label confusion matrix 생성.

현재 `사용자 명세 + 자동 pseudo-label` 경로에서는 5개 행동의 fixed-split 학습 입력이 준비됐다. ST-GCN은 98개 sequence(`[98,60,17,3]`), XGBoost는 standing/sitting/lying CSV 3,350행이며 각 고정 split에 필요한 class가 존재한다. 다만 이는 사람 검수 또는 공식 codebook으로 의미가 확정된 `full_learning_ready`와 동일하지 않으며, 모든 activity row에 `human_reviewed=false`를 유지한다.

8-label 전체 완료 조건은 별도다. `sleeping`, `room_exit`, `no_move_long`은 ST-GCN/XGBoost 학습 class가 아니라 runtime ROI/time rule이고, 사람 검수 semantic truth와 최종 fusion/evaluation이 아직 남아 있다. 위험도 보조 검증은 7,614 approved pose rows 전체에서 source interval 연결 `7,614/7,614`, 누락 `0`, 충돌 `0`으로 끝났지만 semantic activity truth를 증명하지 않는다.
