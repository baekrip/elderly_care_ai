# 삭제 계획

Last updated: 2026-06-11 21:16

이 문서는 `device_transfer/`를 메인 코드 폴더로 유지하기 위한 삭제/정리 계획이다.

---

## 1. 확정 기준

- 메인 코드 기준: `device_transfer/`
- Pi5 기준 폴더: `device_transfer/camera1`
- Orin 기준 폴더: `device_transfer/Edge`
- 문서 기준 폴더: 루트 `docs/`
- 테스트/로컬 도구/플러그인 기준: 루트 `tests/`, `tools/`, `.agent/`, `skills/`
- 기기 이전 기준: `device_transfer/camera1`, `device_transfer/Edge`를 직접 수정한 뒤 SSH/SCP로 기기에 이전한다.

---

## 2. 즉시 삭제 완료

| 삭제 대상 | 결과 | 이유 |
|---|---:|---|
| `device_transfer/camera1/docs/` | 완료 | 기기 실행 묶음 안 문서 중복 제거 |
| `device_transfer/Edge/docs/` | 완료 | 루트 `docs/`만 문서 원본으로 유지 |
| `device_transfer`, `tools`, `tests` 하위 `__pycache__/` | 완료 | 검증 중 생성된 Python 캐시 제거 |
| 루트 `edge/` | 완료 | 기기로 이전되는 Pi5/Orin edge 코드는 `device_transfer/*/edge/`에만 유지 |
| 루트 `server/` | 완료 | Orin 서버 코드는 `device_transfer/Edge/server/`에만 유지 |
| 루트 `shared/` | 완료 | 기기 공통 런타임 코드는 `device_transfer/*/shared/`에만 유지 |
| 루트 `deploy/` | 완료 | `device_transfer`와 중복되는 legacy 전송 묶음 제거 |

---

## 3. 코드 기준 전환

기존 계획은 루트 `edge/`, `server/`, `shared/`, `tools/`를 원본으로 두고 `device_transfer/`를 재생성 산출물로 보는 구조였다.

사용자 지시에 따라 기준을 다음처럼 변경한다.

| 구분 | 새 기준 |
|---|---|
| Pi5 edge 코드 | `device_transfer/camera1/edge/` |
| Pi5 shared 코드 | `device_transfer/camera1/shared/` |
| Orin edge 코드 | `device_transfer/Edge/edge/` |
| Orin server 코드 | `device_transfer/Edge/server/` |
| Orin shared 코드 | `device_transfer/Edge/shared/` |
| Orin tools 코드 | `device_transfer/Edge/tools/` |
| 문서 | 루트 `docs/` |

---

## 4. 보호 조치

`tools/build_deploy_bundles.py`는 더 이상 `device_transfer/`를 삭제/재생성하지 않는다.

새 동작:
- `device_transfer/camera1`, `device_transfer/Edge`가 존재하는지 검증한다.
- `device_transfer/*/docs`가 있으면 실패한다.
- `device_transfer/camera1/server`처럼 Pi5에 불필요한 서버 중복이 있으면 실패한다.
- 기존 legacy `deploy/` 묶음 생성은 차단한다.
- `build_edge_bundle()`, `build_server_bundle()` 호출 시 실패한다.

## 5. 유지 대상

아래 항목은 테스트/로컬 도구/플러그인 역할이므로 유지한다.

| 유지 대상 | 유지 이유 | 정리 기준 |
|---|---|---|
| `tools/` | 로컬 검증, 배포, 학습 보조 도구 | 기기 실행 전용 도구만 `device_transfer/Edge/tools/`에 유지 |
| `tests/` | 로컬 자동 검증 | 테스트가 참조하는 런타임 코드는 `device_transfer` 기준으로 맞춤 |
| `.agent/`, `.codex/`, `.cursor/`, `.omo`, `.codegraph`, `skills/` | 에이전트/플러그인/규칙/로컬 인덱스 | 기기 전송 대상 아님 |
| `.venv/`, `.venv_edge_local/`, `node_modules/` | 로컬 개발 의존성 | Git/기기 전송 대상 아님. 용량 정리는 별도 승인 후 수행 |
| `docs/` | 문서 원본 | `device_transfer` 내부 docs 복사 금지 |
| `scripts/` | systemd 등 운영 보조 템플릿 | 기기 실행본은 `device_transfer/*/scripts/` 기준으로 대조 |

## 6. 검증 후 삭제 후보

아래 항목은 지금 즉시 삭제 대상이 아니라, 참조 검색과 재현 필요성 확인 후 삭제한다.

| 후보 | 이유 | 삭제 전 확인 |
|---|---|---|
| `temp_test/` | 테스트 입력/임시 산출물 가능성 | 현재 테스트나 문서에서 참조하는 샘플 파일 여부 확인 |
| `reports/` | 과거 검증 리포트 누적 | 최신 검증 증거로 필요한 파일만 `docs/진행상황.md`에 링크 후 정리 |
| `runs/` | 학습/실험 산출물 | best model 재현에 필요한 run인지 확인 |
| `evidence/` | 검증 증거 보관 | 발표/보고에 필요한 증거인지 확인 |
| `plans/` | 과거 계획 산출물 | 현재 `docs/구성.md`와 중복되는지 확인 |
| `data/` | 학습/샘플 데이터 가능성 | 학습 재현에 필요한 원본인지 확인 |
| `clip_json/` | 런타임 clip 결과 산출물 | 현재 실기기 검증에 필요한 pending/result 여부 확인 |
| 루트 `*.pt` 모델 파일 | `device_transfer/*/edge/models/`와 중복 가능 | 실제 참조 경로가 루트인지 device_transfer인지 검색 |
| `scratch_debug_frame.jpg` | 디버그 이미지 | 문서/테스트 참조 여부 확인 |
| `run_*.bat`, `trim_*.ps1` | 과거 수동 실행/정리 스크립트 | 현재 실행 가이드와 중복 여부 확인 |
| `.debug-journal.md` | 과거 디버그 기록 | `docs/command.md`와 중복 여부 확인 |

## 7. 다음 삭제 단계

1. `tools/` 안에서 더 이상 쓰지 않는 1회성 테스트 스크립트를 식별한다.
2. `tests/` 안에서 오래된 계약을 검증하는 테스트와 현재 계약 테스트를 분리한다.
3. `temp_test/`, `reports/`, `runs/`, `evidence/`, `plans/`, `data/`, `clip_json/` 중 재현 불필요 산출물을 별도 후보로 분류한다.
4. 루트 모델 파일(`*.pt`)이 `device_transfer` 내부 모델과 중복인지 해시/참조 기준으로 확인한다.
5. 실제 삭제 전 각 항목마다 참조 검색과 최소 테스트를 통과시킨다.

---

## 8. 현재 결론

현재 기기 실행 코드 중복 폴더인 루트 `edge/`, `server/`, `shared/`, `deploy/`는 삭제 완료했다.

기기로 이전되어 써야 하는 실행 파일은 `device_transfer/camera1`, `device_transfer/Edge` 내부에만 둔다.

루트 `tools/`, `tests/`, 플러그인/규칙/로컬 인덱스/가상환경 폴더는 유지한다. 이들은 기기 전송용 실행 폴더가 아니라 로컬 검증/작업용이다.

### 9.4 삭제 실행 스크립트 제안
승인 후 아래 스크립트를 통해 보호 대상을 안전하게 제외한 후 삭제를 수행한다.

#### PowerShell (Windows 로컬 실행용)
```powershell
# 1. 삭제 대상 디렉토리 일괄 정리 (보안 가드 적용)
$TargetDirs = @("temp_test", "evidence", "reports", "experiments", "clip_json")
foreach ($Dir in $TargetDirs) {
    if (Test-Path $Dir) {
        Remove-Item -Path $Dir -Recurse -Force -ErrorAction SilentlyContinue
        Write-Host "Deleted directory: $Dir"
    }
}

# 2. 루트 임시 파일 정리
$TargetFiles = @("scratch_debug_frame.jpg", "export_error.log", "test_result.log", "test_result_utf8.log", "trim_file.ps1", "trim_구성.ps1")
foreach ($File in $TargetFiles) {
    if (Test-Path $File) {
        Remove-Item -Path $File -Force -ErrorAction SilentlyContinue
        Write-Host "Deleted file: $File"
    }
}
```

### 9.5 삭제 후 검증 계획
1. **의존성 검증**: 삭제 완료 후 전체 Python 파일 컴파일 테스트(`python -m compileall .`)를 수행하여 문법적/참조적 단절이 없는지 확인한다.
2. **테스트 스위트 실행**: `pytest` 또는 `tests/` 디렉토리 내의 핵심 유닛 테스트를 실행하여 테스트 파이프라인의 무결성을 입증한다.
3. **런타임 동작 확인**: Orin edge 서버 및 Pi5 websocket 연동이 에러 없이 구동되는지 실행 상태를 검증한다.

## 10. IDE 탐색기 뷰 정리 계획 (플러그인 및 설정 폴더 숨김)

### 10.1 IDE 설정 파일 생성
